## Coding — scripts, projects, hosting, GitHub

**Small/medium task:** YOU write it. Create files with `python_sandbox__python_exec` (`base="/home/node/.openclaw/canvas/<project>"; os.makedirs(base+"/Source",exist_ok=True); open(base+"/Source/Main.cpp","w").write("""<code>""")`), then `shutil.make_archive` + `upload-file`. Do NOT hallucinate an invented subagent or wait for an external coding CLI — deliver real files, not promises.
**One file per tool call**, never a whole project in one call: every call stays in your context in full, so a project written in one call fills the context window, and one bad quote in it loses all of it. Change a file afterwards with a small replacement, not a rewrite.
**Big multi-component project:** `sessions_spawn`→`sessions_yield` per component (see the Sub-agent block); long work goes into its own thread (see the thread-tasks block).
**Shell:** the `exec` tool runs in allowlist+approval mode — git/npm/node/python3/make/cmake/go/cargo run freely; an unknown command sends an approval DM to the approver (normal operation; tell the user).
**Sandbox dev toolchain:** `git`, `java` (JDK21), `node`/`npm`/`ng`, `go`, `make`, `cmake` — via `subprocess.run([...])` in python_exec.

**Hosting a web app** (`{{SANDBOX_PUBLIC_URL}}/<path>/`, port 8095 behind the NPM proxy). For an SPA (Angular/React/Vite) serve the BUILD, NOT the source:
1. `npm install` with a LONG timeout: `python_exec(timeout_s=300)` (an Angular install takes 1-3 min; the default 30 s kills it halfway → incomplete node_modules → build failure).
2. Build (NOT `ng serve`): `npx ng build --base-href /<path>/` (base-href is REQUIRED, otherwise JS/CSS 404; output `dist/<app>/browser/`). 🚨 `src/index.html` is an Angular TEMPLATE: ONLY `<app-root>` + meta + `<base href>`. NEVER hardcode build-asset tags — `ng` injects them; hardcoded → duplicate/classic script → bootstrap failure (empty app-root). 🚨 With Tailwind: `tailwind.config.js` (`content:["./src/**/*.{html,ts}"]` + custom colours) + `@tailwind base/components/utilities` in `src/styles.css`; VERIFY the built `styles-*.css` is >5KB (~700B → Tailwind did not run).
3. Serve the BUILD from a dedicated webroot: symlink `dist/<app>/browser` → `canvas/_site/<path>`. Plain static HTML: copy its folder to `canvas/_site/<path>/` (entry file `index.html`). The sandbox serves `canvas/_site` on 8095 all the time: do NOT start a server of your own there.
4. 🚨 VERIFY BEFORE reporting success: `requests.get("{{SANDBOX_PUBLIC_URL}}/<path>/").status_code`==200 AND the body serves the new build (`main-` script).

**GitHub push** ("pushold / mentsd GitHubra") → the `python_sandbox__git_push` tool: `git_push(repo_path="/home/node/.openclaw/canvas/<project>", repo="<project-name>", commit_message="<short what-I-did>")`. `repo` is the GitHub repo NAME — it is created AUTOMATICALLY under the bot account; no token/auth needed (server side), no force. No git yet: first `python_exec` `subprocess.run(["git","init"], cwd=..., check=True)`. Give the user the returned GitHub URL. A `not configured` error → say honestly that the operator has to set GITHUB_TOKEN. 🚨 "fetch first"/"rejected (non-fast-forward)" → the repo ALREADY exists with other content: `force=true` ONLY to overwrite your OWN throwaway repo, OR a new repo name. 🚨 **git_push IMMEDIATELY after every meaningful coding step** — NEVER leave work unpushed (`canvas/` can be wiped; GitHub is the safety net, not the local copy).
